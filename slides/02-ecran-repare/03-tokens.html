Un design token est une valeur de design nommée

📐

indépendante des plateformes

la même décision pour le web, iOS, Android…

🤝

partagée

entre les métiers, les outils et les technologies

🗣️

un vocabulaire commun

tout le monde parle de la même couleur, avec le même nom

DTCG (Design Tokens Community Group, un groupe communautaire du W3C), Design Tokens Format Module 2025.10, introduction

Wafa : « Les design tokens aident à nommer et partager des décisions de design. Le DTCG, un groupe communautaire du W3C, définit un format pour les échanger entre outils. La version 2025.10 date d'octobre 2025. Son introduction présente les tokens comme un moyen d'exprimer des décisions de design indépendamment des plateformes… »
Wafa : « … pour les partager entre les métiers, les outils et les technologies… »
Wafa : « … et installer un vocabulaire commun. »
Théo : « Donc on peut garder plusieurs nuances, en nommant leur rôle pour savoir laquelle choisir. »

Tokens bruts : des valeurs

red-50
orange-100
orange-200
orange-500
red-800

Une palette finie, nommée par sa valeur.

Wafa : « On garde plusieurs nuances de rouge et d'orange : elles n'ont pas toutes le même rôle. Les tokens bruts nomment les valeurs de la palette ; les tokens sémantiques disent à quoi elles servent. »

Tokens sémantiques : nommés par leur sens

red-50 → --color-primary-soft
red-600 → --color-primary
red-800 → --color-primary-strong

Dans notre modèle, les composants s'appuient sur les noms fonctionnels.

Tokens bruts et sémantiques : une pratique courante, pas une notion définie par le DTCG.

Wafa : « Ici, le token sémantique est nommé par son rôle : à quoi sert la couleur. « primary », c'est la couleur du rôle principal. Dans notre modèle, les composants s'appuient sur ces noms fonctionnels. »
Théo : « Donc si je change un token, tout bouge ? »
Wafa : « Si tout passe par les bons tokens sémantiques, le thème peut changer ces rôles sans modifier chaque composant. »

En CSS : un alias relie le sens à la valeur


:root {
  --red-600: #de1823;
  --color-primary: var(--red-600);
}

En CSS, var() illustre l'idée d'un alias. Le format DTCG définit aussi ses propres références entre tokens.

Wafa : « En CSS, le nom fonctionnel pointe ici vers une valeur de la palette : c'est une illustration du principe d'alias. Ligne 2 : la valeur brute. Ligne 3 : le nom qui dit à quoi elle sert, relié à la valeur par un alias Le format DTCG décrit les références dans son propre format d'échange. Les composants utilisent le nom fonctionnel ; un thème peut lui associer une autre valeur. »

Comment garder une décision de design cohérente, de la maquette jusqu'aux différentes plateformes ?

On peut éviter les recopies manuelles : chacun part d'une source commune.

Le DTCG définit un format d'échange ; Figma, Tokens Studio et Style Dictionary sont des exemples d'outils, pas une intégration automatique.

Wafa : « Comment garder les nuances de rouge et d'orange cohérentes, de la maquette jusqu'aux différentes plateformes ? Les tokens et les outils de traduction peuvent aider à faire circuler ces décisions. »
Wafa : « Le designer choisit sa couleur dans son outil de design, par exemple Figma. C'est la décision. »
Wafa : « Un outil de traduction, par exemple Style Dictionary, convertit cette décision. »
Wafa : « Et chaque plateforme la reçoit dans son langage : CSS pour le web, iOS, Android. »
Wafa : « Avec une chaîne outillée, on peut éviter de recopier les mêmes valeurs à la main. »
